# 元数据匹配与封面下载性能优化

> 状态：**已实施**（2026-10-08，commit `3e0356c`）。方案 1+3 已落地并回归通过。
>
> 适用：无翻译原版 `develop`；公共优化，验收后选择性同步实验版。

## 实施记录（2026-10-08）

- `vndb_client`：`download_cover` 默认**短超时 8s + 0 重试**（新增 `_COVER_TIMEOUT`）；`_http_get` 补 `TimeoutError/OSError` 捕获；`_request_with_retry` 支持自定义重试次数。
- `metadata_matcher`：`match_single/match_batch` 新增 `cover_cb`，有回调时封面异步、不下载。
- `game_manager`：`match_vndb_metadata` / `match_vndb_all` / `match_vndb_for_games` 透传 `cover_cb`。
- `web_bridge`：4 线程封面池（`_queue_cover` + `_download_cover_bg`），下载成功写库 `cover_path` 并定向 `reloadCover`；匹配完成用 `refresh()` 刷元数据。
- 单游戏匹配（右键菜单）复用批量同款进度条 + 取消；批量模式下进度面板上移错开底部批量工具栏。
- 实测：35 游戏 `match_batch` 匹配约 **97s**（此前含封面数分钟）；回归 P0(9)/P1(18) 通过。

## 实测结论（2026-10-07）

用真实库 30 个标题逐游戏计时（隔离，只读库、封面写临时目录）：

| 游戏 | 搜索耗时 | 封面耗时 | 封面大小 |
|---|---|---|---|
| 1 | 0.9s | 24.7s | 185 KB |
| 2 | 2.6s | 22.1s | 246 KB |
| 3 | 0.9s | 14.8s | 114 KB |
| 4 | 2.3s | 14.3s | 125 KB |
| 5 | 3.4s | 35.4s | 314 KB |

- **搜索**（`api.vndb.org`）：单次约 0.9–3.4s，正常。
- **封面**（`t.vndb.org` 图片 CDN）：单张 **14–35s**，文件仅 100–300 KB，等效吞吐约 5–20 KB/s。
- 连通性正常（连接建立约 1s），瓶颈在**下载吞吐**，与用户带宽无关。
- 30 个游戏的实际匹配耗时（用户反馈 5–6 分钟）主要来自**封面串行下载**；搜索本身每游戏仅 1–3s。

**根因**：封面下载与匹配在同一串行链路中同步执行，且 `t.vndb.org` 到当前线路的传输极慢；`_REQUEST_TIMEOUT=15`、`_MAX_RETRIES=2` 还会在超时后重试，进一步放大单张封面的耗时。

## 目标

- 匹配（搜索 + 写库 + 回卡片）不再等待封面下载：用户感知为"元数据即时出现，封面陆续补齐"。
- 封面下载失败或超时**不拖累**匹配整体进度，也不触发长时间重试。
- 保持既有行为：匹配结果与封面正确关联、取消可中断、进度与门禁一致。

## 方案（1 + 3）

### 1. 封面下载与匹配解耦（异步）

- 匹配（`match_single` / `match_batch`）只负责：搜索 → 更新元数据字段 → 写库 → 通知前端刷新卡片。
- 封面下载改为**后台队列**：匹配成功后把封面任务入队，由独立后台线程（或线程池）下载；下载完成后再**定向刷新该卡封面**（复用现有 `reloadCover` / UISync `cover` 域）。
- 不阻塞匹配进度条与任务门禁；匹配任务可在封面尚未下载完时即标记完成。
- 队列中的封面任务应可被**取消事件**中断（与 DEV-TRIAL-02 的取消细化一致）。

### 3. 封面下载短超时 + 不重试

- 为封面下载使用**独立、较短的超时**（例如 5–8s），区别于 API 搜索的 15s。
- 封面下载**失败/超时直接跳过**，不进入重试/退避；记录日志，不阻塞其它封面。
- 被跳过的封面保留"无封面"状态；用户可后续手动重试或再次匹配。

## 落地要点（待实施时细化）

- 后端：
  - `vndb_client.download_cover` 增加可配置超时（或新增 `_http_get(..., timeout=...)`）。
  - 新增封面下载队列 / 工作线程；`match_single` 不再同步调用 `download_cover`，改为入队。
  - 封面完成回调经 UISync 定向刷新对应卡片封面。
- 前端：
  - 匹配进度不等待封面；封面异步到达后单卡重载封面。
- 兼容：
  - 已有本地封面不覆盖；删除/重命名联动逻辑不受影响。

## 验收标准

- 对 30 个未匹配游戏执行批量匹配：**匹配（搜索+写库）总耗时**接近"搜索耗时之和"（约 1–3s/游戏量级），不再被封面拖到数分钟。
- 封面逐步异步补齐；单张封面超时不导致匹配卡顿或整批延迟。
- 取消失效：匹配中取消后，不再发起新的搜索或封面下载；任务门禁正确释放。
- 已匹配卡片与新增封面正确对应，无串图；失败封面可再次触发。

## 边界与未决

- 封面并发度、队列容量、超时具体数值待实施时确定并实测。
- 若线路对 `t.vndb.org` 长期不通，可另议封面镜像 / 代理路径，不在本方案范围。
- 本方案不改变搜索与匹配启发式、不改变数据源选择。
