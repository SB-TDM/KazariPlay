# 本次改动说明（2026-10-08）

> 分支：`develop`（无翻译原版）。本说明记录本轮开发的全部改动与原因，供审阅与后续接手。
> 状态：本轮改动**已本地完成并验证，尚未提交、未打包**。

## 概述

本轮围绕**扫描准确性**、**元数据匹配与封面下载性能/体验**、**多源搜索超时**、**元数据候选应用**四块，共 7 项改动。

---

## 1. 扫描：整棵树规则

- 文件：`core/game_scanner.py`
- 问题：同一游戏目录树里，子目录的 exe（如 `eden PLUS MOSAIC`）被识别成**另一个游戏**，导致一张游戏出多张卡。
- 规则：从扫描根向下，**第一个含有效 exe 的目录**视为"游戏根"；识别后**剪掉其子树**，同一游戏树下只识别一个游戏。父目录无 exe 时不剪枝，所以**合集仍各自识别**。
- 效果：`eden*`（含特典子目录）识别为 1 个。

## 2. 封面下载与匹配解耦

- 文件：`utils/vndb_client.py`、`core/metadata_matcher.py`、`core/game_manager.py`、`ui/web_bridge.py`
- 问题：封面下载与匹配**串行**，且 t.vndb.org 封面很慢（实测单张 15~35s），把整批匹配拖到数分钟。
- 改动：`match_single/match_batch` 新增 `cover_cb`；封面改由 `web_bridge` 后台线程池下载，完成写库并定向 `reloadCover`。匹配本身不再等待封面。
- 效果：35 游戏匹配约 **97s**（此前含封面数分钟）。

## 3. 单游戏匹配进度条

- 文件：`ui/web_bridge.py`、`ui/web_assets/ts/batch.ts`
- 问题：右键卡片的「元数据匹配」无进度反馈。
- 改动：单游戏匹配复用批量同款进度条 + 取消；批量模式下进度面板上移，避免遮挡底部批量工具栏。

## 4. 封面下载参数可配置（设置项）

- 文件：`utils/config.py`、`utils/vndb_client.py`、`ui/web_bridge.py`、`ui/web_assets/partials/settings.html`、`ui/web_assets/ts/settings.ts`
- 问题：封面超时固定 8s，而实测需 15~35s → 多数封面**超时失败、不下载**。
- 改动：设置页新增「封面下载」组：
  - **下载超时**：下拉 30/60/**90**/120/300 秒（默认 90），下载时读取，**即时生效**
  - **最大并发**：下拉 1/2/**4**/6（默认 4），线程池启动时读取，**重启生效**
- 配置项：`config.cover_download = { "timeout": 90, "max_concurrent": 4 }`

## 5. 封面下载可视化（环形转圈）

- 文件：`ui/sync.py`、`ui/web_bridge.py`、`ui/web_assets/ts/state.ts`、`ui/web_assets/ts/cards.ts`、`ui/web_assets/css/cards.css`
- 改动：新增 UISync 域 `cover_progress`——封面下载中，在**可见卡片**封面中心显示环形转圈；结束（成功/失败）收起。
- 约束：**只对已渲染（可见）卡片**显示（配合卡片窗口化）；**失败不重试、不显示**。

## 6. 多源搜索整体超时

- 文件：`core/multi_source.py`
- 问题：混合搜索各源**顺序**查询，无整体上限，最坏可达约 80s 才返回。
- 改动：**并发**发起各源，整次搜索上限 **30s**，超时返回已完成候选（不再累加等待）；结果按源配置顺序还原。

## 7. 元数据候选字段勾选

- 文件：`ui/web_bridge.py`（`applyCandidate`）、`ui/web_assets/ts/form.ts`、`ui/web_assets/partials/meta_apply.html`、`main.py`、`ui/web_assets/ts/pywebview.d.ts`
- 问题：编辑界面点候选只做"填空"（仅当本地为空才填），无法选择要替换的字段。
- 改动：点候选后弹**字段选择框**（交互参考「重新定位预览」）：标题/开发商/发售日/评分/简介/时长/封面，每行显示 `当前值 → 候选值`；**空白字段默认勾（将添加）、已有值默认不勾（覆盖需手动勾）**；可全选/取消全选；只应用勾选字段。
