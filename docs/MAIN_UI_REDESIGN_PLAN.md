> 修订：V1.1，2026-10-09；文档收尾复核：2026-10-10。状态：**主界面方向已确认；本轮完善计划，界面代码尚未开始实施**。

> 旧计划：[UI_OPTIMIZATION_DISCUSSION.md](UI_OPTIMIZATION_DISCUSSION.md)（2026-10-07 评审草案）。按 §4 逐项承接，不自动授权全量建议，也不一刀切排除其他窗口的缺陷修复。
> 基本约束：沿用原版代码，只改前端界面；不新增产品功能、数据库字段、桥接口或运行时业务模块，不迁移框架，不大规模重构。允许必要的 DOM/CSS、现有模块内的小函数与临时 UI 状态。

## 1. 依据优先级与范围

1. 用户已确认的范围与交互、项目数据保护和分支纪律优先。
2. 主界面外观/交互与旧计划冲突时，修订计划文字，以已确认原型为准；不能把原型演示逻辑直接当生产实现。
3. 原版的真实数据、桥契约、游戏 ID、已有功能及性能机制继续保留。
4. 旧计划的可读性、键盘路径、异步正确性和回归要求继续承接。缺陷是否存在、是否已经修复，以选定提交和新鲜验证结果为准。
5. 原型与质量要求有实测冲突时，列出具体位置、影响与最小调整供用户确认；不得自行降低要求或全局换色。

本轮主界面范围：图标侧栏、副标题栏、游戏卡片信息行、收藏夹导航浮层、遮罩、主界面现有操作入口。右下角两圆按钮、侧栏底部三按钮按既有确认保留。

非目标：新主页仪表盘、账号系统、云同步、自动创建演示分类、新排序数据模型、翻译功能、全站主题重设计、React/Vue/Tauri 迁移、桥服务化、数据库或 Python/C++ 重构。

## 3. 已确认的主界面目标

| 区域 | 目标与保留边界 |
|---|---|
| 布局 | 左侧图标列 + 主区。收藏夹为脱流浮层；在相同数据、滚动位置和视口下，开合不改变卡片列数、位置、尺寸或搜索框位置 |
| 标题栏 | 保留原版版本来源、拖拽/缩放、最小化/最大化/关闭能力。原型隐藏窗口按钮只是浏览器演示，不是删除产品能力的依据 |
| 侧栏 | 主页、全部作品、我的最爱、收藏夹入口；底部个人入口占位、亮暗切换、设置。星星代表全局 `fav`，不是收藏夹。主页复用既有列表，不开发新主页；个人入口不开发账号功能 |
| 侧栏规格 | 1600px 参考视口宽 72px；上部按钮 46×44、底部按钮 44×44、圆角 14px。原型上部 active 为实色粉底，不能统一描述成渐变；底部三个按钮保留此前确认外观 |
| 副标题栏 | 左：当前视图名/数量；中：搜索；右：批量选择/当前排序。搜索与命令共同排版，面板开合不移动；不写死屏幕坐标。宽视口参考高 70px，允许窄窗口自然换行 |
| 数量与搜索 | 数量基于真实数据和当前筛选，不统计窗口化 DOM 数量；搜索时显示匹配数/当前视图总数。保留开发商、标签等现有搜索能力，即使卡片不再展示开发商 |
| 卡片 | 沿用原版封面卡结构、角标、勾选、点击详情及右键能力。底部 31px 单行：左游戏名省略号、右数字评分；完整名称供 tooltip/可访问名称。开发商留在详情/数据中，不删除字段 |
| 卡片尺寸 | 154×210 是默认 medium，不覆盖用户已有 small=132×180、large=180×245 设置。各档内尺寸稳定，CSS、窗口计算、占位高度及 gap 联动 |
| 数字评分 | 展示使用真实 `rating`，按原型一位小数（如 4.0），不换算为十分制、不新增评分源。0/空值语义先核对原数据约定，不能把“未评分”伪造成实评分；评分编辑仍复用原流程 |
| 收藏夹 | 参考宽 248px，窄桌面原型有 220px 规则；半透明与背景模糊按原型。左边贴图标列右边，顶部**紧贴副标题栏底部**，底部到主区底部，不占卡片布局列 |
| 收藏夹数据 | 用原版分组/子分类和真实数量，保留折叠、筛选、新建、重命名、删除、排序及多对多归类。原型“状态/题材”等是示例，不初始化进用户库 |
| 遮罩 | 只覆盖副标题栏以下卡片区，浅色 `rgba(255,246,249,.55)`、暗色 `rgba(24,19,32,.5)`。覆盖范围包含区内 FAB；点被遮卡片/空白/FAB只收起面板，不穿透到详情、收藏、批量或添加动作 |
| 遮罩与工具栏 | 搜索、排序及左侧导航仍可用；面板内部点击不关面板。收起后遮罩不拦截点击，后台卡片恢复交互；开合不清空现有筛选和选择 |
| FAB | 保留右下两个 54px 粉色渐变圆按钮，刷新在上、添加在下及现有菜单；不搬回副标题栏，不复制原型的假扫描/假成功提示 |
| 亮暗与动效 | 匹配原型已确认的主界面外观；约 0.28s 面板/遮罩动效。沿用原版主题持久化，减少动效模式同时覆盖 transition 和 animation |

“继续游玩”不再作为原型侧栏独立入口，这是已选主界面布局的结果，不为此另造页面；保留既有筛选逻辑、数据和可能的引用，不顺手删除业务代码。若发现仍有必要的用户路径依赖该入口，记录后确认承接方式，不擅自增加替代导航。

## 5. 生产落地方式与允许修改面

### 5.1 必须保留的数据与刷新链路

- 继续使用 `App.data`、`App.ui.state`、`window.__app`、UISync、现有 bridge 与 TypeScript 经典脚本加载顺序。
- `collectionTree` 保持唯一 ID，搬到浮层即可复用 `renderCollectionTree()`；没有多容器需求，不为搬位置增加参数化抽象或第二套树数据。
- 卡片信息要同步 `buildCard()` 与 `renderCards()` 的复用更新路径；名称更新、评分更新、删除及同名游戏按真实 gid 处理。
- 视图标题与数量在 `games.ts` 的现有刷新链路统一维护，检查 `renderAll()` **和绕过它的 `applyGamesDelta()`**，以及收藏夹树变化；不能用强制全量刷新补漏。
- 保留 `applyCoverSize()` 三档与窗口化计算，不因原型默认大小而废掉现有设置。
- “排序按钮显示当前规则”不授权重写排序算法。本轮静态发现 `games.ts/filterGames()` 的时间分支使用 `last_played`，而入口存在“添加时间”文案：G0 用 fixture 核实并决定准确展示名称；不得新增时间字段或偷换比较键。

### 5.3 技术建议的修正与选择原则

1. **定位**：优先让浮层和遮罩共享同一个卡片视口参照系；可在现有结构局部调整，不重排业务架构。无法共享时，统一函数按各自定位父容器换算坐标；跟踪工具栏实际尺寸变化，必要时用已有浏览器能力 `ResizeObserver`。观察器只绑定一次并合并写入，不逐卡测量。
2. **CSS calc**：只计算变量，不能自动感知字体/DPI/换行后的真实高度。仅在固定高度确实覆盖全部验收场景，或变量由实际尺寸同步时适用；不以此为理由删除已解决缝隙的观测路径，不用固定 `-1px` 掩盖时序/参照系问题。
3. **图标**：mask 和内联 SVG 的 `currentColor` 都可跟随主题。沿用已有本地资源和样式是默认选择；不要为换色引入库或全量转换。涉及资源加载时验证 `main._load_html()` 的实际内联路径，不能只验证 file URL。
4. **状态**：允许在既有模块内一个开合函数和必要 UI 字段；不新增通用 SidebarManager、任务服务、全局状态框架。外层模态关闭/焦点行为通过既有机制对接。
5. **结构优化候选**：CSS Grid 三段工具栏、全库筛选缓存等只有出现明确问题和比较结果才提出；**仍为待批准候选**，不是本计划默认重构任务。
